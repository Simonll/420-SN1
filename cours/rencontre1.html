Tolérance zéro pour le plagiat

Si un travail remis est suspecté de plagiat (code copié sur un ou une collègue, généré par une IA, ou utilisant des notions non vues en classe), voici ce qui se produira :

  • Preuve formelle : Si nos outils détectent un plagiat de façon catégorique, c'est la note de 0 automatiquement.
  • Validation requise : Si le doute est fort mais nécessite une vérification, vous serez convoqué(e) au bureau de votre enseignant(e). Vous devrez expliquer et démontrer que vous maîtrisez parfaitement le code remis. L'incapacité à expliquer le fonctionnement de votre propre code entraînera la note de 0 (ne pas comprendre ce qu'on a remis équivaut à avoir triché).
Entraide vs Plagiat : Comment tracer la ligne ?

En programmation, la limite entre « s'entraider » et « copier » peut parfois sembler floue. Voici nos règles d'or pour collaborer sainement :

  • Ne partagez jamais vos fichiers ou blocs de code. Même avec de bonnes intentions, la personne aidée finira souvent par copier-coller sans réfléchir.
  • Expliquez la logique, pas la syntaxe. Vous avez tout à fait le droit de faire des dessins, d'expliquer un algorithme ou de reformuler un problème, mais vous ne devez jamais écrire (ou dicter) le code à la place de quelqu'un d'autre.
  • En cas de doute, levez la main ! Votre enseignant(e) est la meilleure personne pour vous décoincer.

Introduction

La programmation, c’est l’art de donner des instructions précises à une machine pour qu’elle accomplisse une tâche. Contrairement à un humain, qui peut comprendre le contexte ou improviser, un ordinateur est totalement logique. Il exécute les instructions exactement comme elles sont écrites, sans les interpréter, et toujours dans l’ordre prévu.

Dans un monde de plus en plus numérique, une frontière invisible se dessine entre les simples utilisateurs de technologies et ceux qui en comprennent les rouages. Apprendre à programmer permet de franchir cette frontière : cela augmente notre littératie informatique et nous aide à décoder le langage des machines. Pour de futurs scientifiques ainsi que pour les futurs professionnels de la santé (médecine, pharmacie, recherche clinique, biotechnologies), c'est une compétence de plus en plus incontournable. Qu’il s’agisse d’analyser de grands ensembles de données génétiques, de modéliser des phénomènes biologiques, de traiter de l'imagerie médicale ou d'interagir avec des outils de bio-informatique, comprendre le code vous permet de cesser d'être de simples spectateurs pour devenir des acteurs du changement.

Il existe de nombreux langages de programmation, chacun avec ses forces et ses usages. Certains sont conçus pour la performance (comme C ou C++), d’autres pour la simplicité et la lisibilité. C’est le cas de Python, un langage très apprécié des débutants. Sa syntaxe claire permet de se concentrer sur les concepts sans être ralenti par des règles complexes.

Python est aussi largement utilisé dans des domaines comme l’intelligence artificielle, l’analyse de données et la modélisation scientifique et médicale, grâce à un vaste écosystème de bibliothèques.

Mais attention : il nexiste pas un langage unique pour tout faire. Par exemple :

C/C++ : idéals pour les logiciels qui doivent être rapides et proches du matériel (comme les logiciels de dispositifs médicaux ou d'imagerie lourde).

JavaScript : incontournable pour le développement web.

Kotlin et Swift : spécialisés dans les applications mobiles (comme les applications de suivi de santé).

R et Python : très utilisés pour les statistiques, l’épidémiologie, l’analyse de données et la recherche scientifique.

Pourquoi apprendre à programmer en sciences?

En sciences, savoir programmer est souvent un atout majeur, voire une nécessité. Que ce soit en biologie, en physique ou en chimie, la programmation permet de :

  • Modéliser des phénomènes complexes ;

  • Analyser des données expérimentales ;

  • Simuler des processus naturels.

Quelques exemples concrets :

  • Biologie et Santé : analyser des séquences génomiques, modéliser l’évolution d’une population ou traiter des données d'imagerie médicale ;

  • Mathématiques : résoudre numériquement des équations différentielles ou visualiser des fonctions en 3D ;

  • Chimie/biochimie : étudier la cinétique de réactions chimiques ou manipuler des structures moléculaires ;

  • Géologie : analyser des relevés sismiques ou modéliser l’érosion d’un terrain au fil du temps ;

  • Physique : simuler la trajectoire d’un objet ou l’interaction entre des particules fondamentales.

Plus qu'un simple outil technique, la programmation modifie profondément votre manière de penser. Elle façonne ce qu'on appelle la pensée informatique : une démarche intellectuelle qui force à décomposer un problème complexe en sous-éléments gérables, à identifier des structures répétitives et à formuler des solutions avec une clarté et une rigueur absolues. Cette nouvelle gymnastique d'esprit transforme durablement la façon dont un scientifique structure son raisonnement face à l'inconnu, renforçant des compétences transversales cruciales comme l'esprit critique et la résolution de problèmes.

Enfin, la maîtrise de Python (ou d’un autre langage) ouvre la porte à des domaines en forte croissance, comme la science des données ou l’intelligence artificielle, des outils aujourd'hui omniprésents dans la recherche scientifique, médicale et industrielle.

✅ En résumé : apprendre à programmer, ce n’est pas juste utile — c’est souvent indispensable pour comprendre, modéliser et explorer le monde scientifique.

Fonctionnement de Python et outils de développement

La machine ne fait aucune déduction : elle suit les instructions exactement comme elles sont écrites, dans l’ordre, sans se poser de questions.

Idée importante

Une expression produit toujours une valeur.

En mathématiques, une expression est quelque chose qu’on peut calculer.

Elle peut contenir :

  • des nombres
  • des constantes (ex. : π\piπ)
  • des variables (ex. : rrr)
  • des opérations (+++, −-−, ×\times×, ///, etc.)

Exemple :

2πr2\pi r2πr

Cette expression représente la circonférence d’un cercle.

  • 222 et π\piπ sont des constantes
  • rrr est une variable (le rayon)

Pour obtenir une valeur :

  1. On remplace la variable (r=2r = 2r=2)
  2. On calcule :

2×3,1416×2=12,56642 \times 3{,}1416 \times 2 = 12{,}56642×3,1416×2=12,5664

En programmation, c’est le même principe :

Une expression est quelque chose que l’ordinateur évalue pour produire une valeur.

La différence importante : Une expression peut contenir autre chose que des nombres.

Par exemple :

  • du texte (chaînes de caractères)
  • (plus tard) des fonctions
  • (plus tard) des valeurs booléennes

Voici quelques exemples d'expressions en Python :

  • 5 → vaut 5 (type : int)
  • "5" → vaut "5" (type : str)
  • 5 + 3 → vaut 8
  • "5" + "3" → vaut "53"

Opérateurs identiques, mais résultat différent selon le type de données (c'est la surcharge de l'opérateur +).

Opérateur modulo : %​

Le modulo est une opération mathématique qui consiste à trouver le reste d'une division entière. Imaginons qu'on souhaite connaitre le résultat de 17 modulo 5 :

  1. On se demande : "Combien de fois 555 entre-t-il entièrement dans 171717 ?"
  2. La réponse est 3 fois (3×5=153 \times 5 = 153×5=15).
  3. On calcule ensuite la différence : 17−15=217 - 15 = 217−15=2.
  4. Le chiffre 222 est le reste.

En mathématiques et en programmation, on dira que 17 modulo 5 est égal à 2.

L'opérateur modulo est très utile par exemple pour vérifier si un nombre est pair ou impair, et dans de nombreux autres contextes. Par exemple :

  • 0 % 2 retourne 0 (pair, il n'y a pas de reste)
  • 1 % 2 retourne 1 (impair, il y a un reste de 1)
  • 2 % 2 retourne 0 (pair)
  • 3 % 2 retourne 1 (impair)
  • 4 % 2 retourne 0 (pair)
  • 5 % 2 retourne 1 (impair)
  • ...

Opérateurs de division : / et //​

Dans la console, tapez les expressions 11 / 3 et 11 // 3 pour voir la différence entre les deux.

  • L'opérateur de division / se comporte comme la division classique que l'on connait bien et retourne 3.6666.... Le résultat est toujours un nombre avec décimale (float), par exemple 4 / 2 va retourner 2.0 et non 2.

  • L’opérateur de division // conserve uniquement la partie entière de la division. Il n’y a aucun arrondi : la partie décimale est simplement ignorée. Par exemple, 11 // 3 retourne l’entier (int) 3.

Pour résumer :

  • 11 / 3 retourne 3.6666...
  • 11 // 3 retourne 3
  • 11 % 3 retourne 2

Priorité des opérateurs​

Les opérateurs n'ont pas tous la même priorité, c'est-à-dire que certains sont évalués avant d'autres. Par exemple, dans l'expression 10 + 3 * 2, la multiplication est effectuée avant l'addition, donc le résultat est 16.

On dit que la multiplication a une priorité plus élevée que l'addition. Pour voir la liste complète des priorités, consultez l'aide-mémoire sur les opérateurs (onglet Priorité des opérateurs).

Les parenthèses () sont des opérateurs qui permettent de regrouper des expressions pour forcer l'ordre d'évaluation. Par exemple, si on veut que l'addition soit effectuée en premier, on peut écrire (10 + 3) * 2, ce qui donne 26 comme résultat.

Par exemple, dans la console, tapez les expressions 10 + 3 * 2 et (10 + 3) * 2 pour voir la différence entre les deux.

Opérandes et types de résultats​

Les opérandes (telles que 10 et 3 dans l'expression 10 + 3) peuvent être des valeurs (comme 10 et 3), mais pourraient aussi être des variables, un élément d'un tableau, une expression, etc.

La valeur résultante de l'utilisation d'un opérateur arithmétique peut être de type int (nombre entier) ou float (nombre décimal), selon l'opérateur ET selon les opérandes. Les types sont expliqués plus en détail dans l'onglet Type de cette semaine.

Par exemple, l'opérateur + peut faire la somme de deux nombres, mais utilisé avec des chaînes de caractères (str), il va faire la concaténation (collage) de ces chaînes :

  • 10 + 3 retourne 13 (int)
  • "10" + "3" retourne "103" (str)

Un autre opérateur très utile est l'opérateur d'affectation =, qui permet de stocker une valeur dans une variable.
Il sera étudié dans l'onglet Variables.

Types

En programmation, les valeurs que l'on manipule ont un type, et le type d'une valeur détermine comment on peut l'utiliser et quelles opérations sont possibles avec cette valeur.

Voici les types de données de base pour débuter en Python :

TypeDescriptionExemple
intNombre entier42
floatNombre décimal3.14
strChaîne de caractères"Alice"
boolBooléen (vrai ou faux)True
  • Un nombre entier (int) s'écrit simplement avec des chiffres, comme 42 ou -99.
  • Un nombre décimal (float) s'écrit avec une partie entière et une partie décimale séparées par un point, comme 3.14 ou -0.001.
  • Une chaîne de caractères (str) s'écrit entre guillemets, comme "Alice" ou 'Bonjour!'. On peut utiliser des guillemets simples ('') ou doubles (""), mais il faut être cohérent.

    L'expression "123" est une chaîne de caractères, pas un nombre entier!
    Si vous voulez un nombre entier, il faut écrire 123 sans guillemets.

  • Un booléen (bool) est une valeur qui peut être soit True (vrai) soit False (faux). Ce sont les deux seules valeurs possibles pour un booléen.

    L'expression True est un booléen, pas une chaîne de caractères!
    Si vous voulez une chaîne de caractères, il faut écrire "True" ou 'True' entre guillemets.

type()

Python possède une fonction permettant de connaître le type d'une expression, la fonction type().

Changement de type

On peut changer le type d'une expression en utilisant des fonctions de conversion.
Par exemple, pour convertir un entier en chaîne de caractères, on utilise la fonction str().
Pour convertir une chaîne de caractères en entier, on utilise la fonction int().

Voici quelques exemples, essayez-les dans la console :

type(str(42))        # Convertit l'entier 42 en chaîne de caractères
type(int("42"))      # Convertit la chaîne de caractères "42" en entier
type(float(3))       # Convertit l'entier 3 en nombre décimal
type(float("3.14"))  # Convertit la chaîne de caractères "3.14" en nombre décimal
Polymorphisme des opérateurs

Certains opérateurs se comportent différemment selon le type de leurs opérandes.
Par exemple, l'opérateur + peut faire la somme de deux nombres ou concaténer deux chaînes de caractères.

Voici quelques exemples, essayez-les dans la console :

5 + 3                # Addition de deux entiers
"coucou " + "Alice"  # Concaténation de deux chaînes de caractères
"coucou " + str(81)  # Concaténation d'une chaîne de caractères et d'un entier converti en chaîne

Variables

Les variables servent à stocker des informations manipulées par une application.
Elles vont être stockées temporairement dans la mémoire vive de l'ordinateur (la RAM).

Syntaxe pour créer une variable

Il faut écrire le nom qu'on souhaite donner à notre variable, suivi de l'opérateur d'affectation =, suivi d'une expression :

nom_de_ma_variable = expression
  • nom_de_ma_variable est le nom de la variable, qui doit être unique.
  • = est l'opérateur d'affectation, qui permet de stocker la valeur de l'expression dans la variable.
  • expression est une expression qui peut être : une valeur, une opération mathématique, ou même une chaîne de caractères.

L'expression est d'abord évaluée, puis la valeur résultante est stockée dans la variable.

  • = n'est pas un symbole d'égalité, comme en mathématiques, mais un symbole d'affectation.
  • On calcule d'abord l'expression, ce qui nous donne une valeur et un type.
  • Puis on affecte cette valeur et ce type à nom_de_ma_variable.
astuce

L'opérateur d'affectation = a une priorité plus basse que les opérateurs arithmétiques, et donc l'expression à droite est évaluée avant, puis la valeur résultante est affectée à la variable.

Exemples :

x = 5 * 6           # (5 * 6) est évalué, puis le résultat (30) est affecté à x
y = 2 * x           # (2 * x) est évalué, puis le résultat (60) est affecté à y
Voir le contenu d'une variable

Pour voir ce qui est stocké dans une variable, il suffit de taper son nom dans la console et d'appuyer sur Entrée.
Par exemple, si vous avez créé une variable x, tapez simplement x dans la console et appuyez sur Entrée.
Vous verrez la valeur de x s'afficher :

>>> x = 42
>>> x
42
Noms des variables

Les variables sont comme des boîtes dans lesquelles on peut mettre des valeurs.
On peut les nommer comme on veut, tant que le nom est unique et respecte certaines règles.

Chaque variable possède un nom unique permettant de l'identifier.

En mathématiques, nous sommes habitués d'utiliser des noms de variables comme xxx ou yyy.
En programmation, on essaie d'utiliser des noms plus significatifs de l'information que l'on va stocker dans la variable. Par exemple, si on stocke la température d'une journée, on pourrait nommer la variable temperature_journee.

Règles pour nommer une variable​

  • Les noms de variables peuvent contenir uniquement des lettres, des chiffres (0-9) et des underscores _.
  • Les noms de variables ne peuvent pas commencer par un chiffre.
  • Les noms de variables ne peuvent pas contenir d'espaces, de caractères spéciaux (comme !, @, #, etc.)
  • Les noms de variables ne doivent pas être des mots réservés du langage Python (comme if, else, while, for, etc.).
  • Il est fortement recommandé de ne pas utiliser d'accents dans les noms de variables, même si Python les accepte.
  • Par convention :
    • Les noms de variables doivent être :
      • En minuscules : si le contenu de la variable peut évoluer en cours d'exécution du programme.
      • En majuscules : si le contenu de la variable ne devrait jamais être modifié (ex : la valeur de PI est immuable).
    • Si le nom est composé de plusieurs mots, on utilise un underscore _ pour les séparer (par exemple, temperature_journee).

Voici quelques exemples de noms de variables :

rayon_cercle = 20                         # valeur de type int
PI = 3.1416                               # valeur de type float (avec un point, pas une virgule!)
nom_element_chimique = "Hydrogène"        # valeur de type str (les guillemets sont importants!)
est_halogene = True                       # valeur de type bool
circonference_circle = rayon_cercle * PI  # valeur de type float contenant le résultat d'une expression

# Afficher le contenu des variables à l'aide de la fonction "print()"
print("*** VALEURS DES VARIABLES : ***")
print("rayon_cercle :", rayon_cercle)
print("PI :", PI)
print("nom_element_chimique :", nom_element_chimique)
print("est_halogene :", est_halogene)
print("circonference_circle :", circonference_circle)
Les variables peuvent... varier!

Le contenu d'une variable peut être modifié au fur et à mesure de l'exécution des instructions à l'aide de l'opérateur d'assignation =. Dans l'exemple ci-dessous, la variable "resultat" est modifiée 3 fois.

nombre1 = 10
nombre2 = 20
nombre3 = 30
resultat = nombre1 + nombre2
resultat = resultat + nombre3
resultat = resultat / 3
print("resultat :", resultat)

GitHub joue un rôle similaire, mais il est conçu spécifiquement pour le code source et s'appuie sur Git pour offrir des fonctionnalités bien plus puissantes.

Git est un outil qui roule sur votre ordinateur et qui enregistre l'historique de vos modifications. C'est ce qu'on appelle un système de contrôle de version.

GitHub, lui, est la plateforme en ligne qui héberge vos projets Git et permet de les partager, de les synchroniser et de collaborer avec d'autres développeurs.

En résumé : Git gère l'historique de votre code en local, GitHub le met dans le nuage - comme OneDrive, mais en beaucoup plus puissant.

Le dépôt de code

Un dépôt de code (ou repository, souvent abrégé repo) est un espace de stockage GitHub qui contient tous les fichiers d'un projet ainsi que l'historique complet de toutes les modifications qui y ont été apportées depuis sa création.

On peut le voir comme un dossier de projet intelligent qui se souvient de tout ce qui s'y est passé :

  • Quels fichiers ont été modifiés
  • Qui les a modifiés
  • Quand les modifications ont été faites
  • Pourquoi elles ont été faites (grâce aux messages de description)
L'ensemble de modifications (commit)

Un ensemble de modifications (ou commit) représente un regroupement logique de changements sauvegardés dans le dépôt à un instant précis.

Imaginez que vous travaillez sur un fichier Python et que vous ajoutez une nouvelle fonction.
Une fois votre travail terminé, vous créez un commit pour sauvegarder ces changements. Ce commit contient :

  • La liste de tous les fichiers modifiés
  • Un message décrivant ce qui a été fait (ex : "Ajout de la fonction calcul_moyenne")
  • La date et l'heure de la sauvegarde
  • L'identité de l'auteur
Bonne pratique

Un bon commit regroupe des modifications qui vont ensemble logiquement.
Son message doit être clair et résumer en quelques mots ce qui a été fait.
Exemples :

  • ✅ "Correction du calcul de la superficie"
  • ✅ "Ajout de la validation des entrées utilisateur"
  • ❌ "modifs" — trop vague, inutile!
Les opérations principales : clone, commit, push et pull

Voici les quatre opérations que vous utiliserez le plus souvent pour interagir avec un dépôt GitHub :

clone - Copier le dépôt sur votre ordinateur​

Cloner un dépôt, c'est comme télécharger un projet sur votre ordinateur. Votre IDE va créer un dossier contenant tous les fichiers du projet ainsi que l'historique complet de toutes les modifications qui y ont été apportées.

Pour un repo donné, cette opération est effectuée :

  • sur votre ordinateur personnel : une seule fois
Dépôt GitHub (nuage)  ─── clone ───▶  Copie locale (votre ordinateur)

commit - Sauvegarder vos modifications localement​

Commiter, c'est prendre un instantané de vos modifications à un moment précis, comme une photo de l'état de votre projet. Chaque commit est accompagné d'un message que vous rédigez vous-même pour décrire ce qui a été fait — c'est ce message qui rendra votre historique lisible et utile plus tard. Attention : un commit ne fait que se sauvegarder localement sur votre ordinateur, il n'envoie rien vers GitHub. C'est le rôle du push.

Fichiers modifiés ─── commit ───▶ Historique local (votre ordinateur)

push - Envoyer vos modifications vers GitHub​

Pousser vos commits, c'est mettre GitHub à jour avec votre travail local. Tant que vous n'avez pas fait de push, vos commits n'existent que sur votre ordinateur : GitHub ne les connaît pas encore. C'est donc une étape indispensable pour ne pas perdre votre travail et pour le rendre accessible depuis n'importe quel autre ordinateur.

Copie locale (votre ordinateur) ─── push ───▶ Dépôt GitHub (nuage)

pull - Récupérer les dernières modifications depuis GitHub​

Tirer les modifications, c'est mettre votre copie locale à jour avec ce qui se trouve sur GitHub. C'est particulièrement utile si vous avez travaillé depuis un autre ordinateur depuis votre dernière session. Bonne habitude : toujours commencer une séance de travail par un pull, pour être certain.e de travailler sur la version la plus récente de votre code.

Dépôt GitHub (nuage) ─── pull ───▶ Mise à jour de la copie locale (votre ordinateur)
Guide pour VS Code

VS Code intègre des outils Git très puissants. Vous pouvez cloner, commiter, pousser et tirer des modifications directement depuis l'interface, sans avoir besoin d'un autre logiciel.

commit et push : une combinaison courante

En pratique, on fait souvent un commit suivi d'un push pour sauvegarder notre travail localement et le rendre accessible sur GitHub.
VS Code (et la plupart des IDEs) propose une option pour faire les deux en une seule étape, ce qui peut être très pratique pour gagner du temps.

Chaque fois que vous avez terminé un exercice, ou bien créé une nouvelle fonctionnalité dans votre code, ou corrigé un bug, faites un commit-push (un commit suivi d'un push) pour ne pas perdre votre travail.

Le fichier .gitignore

GitHub est avant tout une plateforme conçue pour héberger des fichiers légers contenant du code source.
Par principe, certains éléments ne doivent jamais figurer dans un dépôt Git :

  • Les fichiers volumineux : ils ralentissent les opérations de clonage et de mise à jour.
  • Les fichiers de configuration d'IDE : par exemple, le dossier .vscode de VS Code, qui est propre à votre environnement de travail local et n'a aucune utilité pour les autres.
  • Les fichiers générés : tout ce qui peut être produit automatiquement par l'exécution de votre programme (images, fichiers texte, etc.).

Le fichier .gitignore est un fichier optionnel placé à la racine de votre dépôt de code et sert à indiquer à Git d'ignorer de tous les commits certains fichiers ou dossiers en fonction de modèles (patterns) définis à l'intérieur. Les fichiers listés dans .gitignore ne seront jamais inclus dans vos commits, même par accident.

Exemple de fichier

Un .gitignore typique pour un projet Python pourrait contenir :

# Exclusion des fichiers propres à votre environnement/configuration de travail local
.idea/
.vscode/
.venv/

# Fichiers Python compilés
__pycache__/
*.pyc
*.pyo

Cela exclut automatiquement les dossiers de configuration des IDEs et les fichiers de cache Python.

Le fichier README.md

La plupart des dépôts GitHub contiennent un fichier nommé README.md à leur racine.
GitHub l'affiche automatiquement sur la page d'accueil du dépôt : c'est la carte de visite de votre projet.

On y trouve typiquement une description du projet, des instructions pour l'utiliser, et toute autre information utile pour quelqu'un qui le découvre pour la première fois.

Le README.md est écrit en Markdown, un format de texte simple qui permet de structurer du contenu (titres, listes, gras, liens, blocs de code…) de façon lisible aussi bien en texte brut que rendu par GitHub. La recette sur les fichiers Markdown vous explique comment en créer un.

Environnement virtuel

Python de base permet déjà de faire beaucoup de choses : faire des calculs, afficher du texte, manipuler des listes, etc. Mais pour des tâches plus spécialisées (générer des graphiques, analyser des données, faire du traitement d'images), des personnes ont développé des extensions que l'on peut ajouter à Python. Ces extensions s'appellent des bibliothèques (ou librairies). Vous en utiliserez plusieurs dans ce cours, comme Matplotlib pour les graphiques, NumPy pour manipuler des données numériques ou Pandas pour l'analyse de données. Le concept de bibliothèque sera vu en détail à la rencontre 02.

Le problème? Ces bibliothèques évoluent dans le temps. De nouvelles versions sont régulièrement publiées, avec de nouvelles fonctionnalités, et ces versions ne sont pas toujours compatibles entre elles. Imaginez que vous travaillez sur deux projets différents : le projet A a besoin de la version 1.0 d'une bibliothèque, et le projet B a besoin de la version 2.0 de cette même bibliothèque. Si vous installez les deux sur votre ordinateur sans précaution, elles risquent de se nuire mutuellement.

La solution? L'environnement virtuel, une sorte de bulle isolée propre à chaque projet, qui contient sa propre version de Python et ses propres bibliothèques, sans interférer avec les autres projets ni avec l'installation globale de Python sur votre ordinateur.

Concrètement, un environnement virtuel est un dossier (nommé .venv par convention) créé à la racine de chaque projet.
Il contient tout ce dont le projet a besoin pour fonctionner.

Le dossier .venv dans votre IDE

La plupart des IDEs modernes facilitent la gestion des environnements virtuels.

  • VS Code : Lorsque vous ouvrez un dossier contenant un projet Python, VS Code détecte votre interpréteur. Si vous n'avez pas d'environnement virtuel, il vous proposera d'en créer un. Il l'activera ensuite automatiquement dans le terminal intégré.

Vous trouverez la recette pour créer un environnement virtuel dans VS Code.

  • PyCharm : Crée et active automatiquement un environnement virtuel pour chaque nouveau projet.

Le dossier .venv contient :

  • Scripts/ (Windows) ou bin/ (Mac/Linux) : une copie locale de Python et pip (l'outil qui installe les bibliothèques) réservée à ce projet uniquement
  • Lib/site-packages/ : les bibliothèques installées pour ce projet (ex : Matplotlib, Pandas) ; elles sont isolées des autres projets et de l'installation globale de Python
  • pyvenv.cfg : un fichier de configuration qui indique quelle version de Python est utilisée
Ne jamais commiter .venv sur GitHub!

Le dossier .venv peut être très volumineux, car les bibliothèques installées sont souvent volumineuses, et certaines configurations sont entièrement propres à votre machine.
Il n'a donc aucune raison d'être partagé sur GitHub : quelqu'un qui clone votre projet n'a qu'à recréer son propre environnement virtuel de son côté.

C'est pourquoi le fichier .gitignore devrait exclure automatiquement ce dossier. Assurez-vous de ne jamais le retirer de votre .gitignore!

Et les bibliothèques installées, alors?

Même si le dossier .venv n'est pas envoyé sur GitHub, il existe une façon de partager la liste des bibliothèques nécessaires à un projet.

Dans les projets Python, on utilise souvent un fichier appelé :

requirements.txt

Ce fichier contient les bibliothèques à installer, parfois avec leur numéro de version :

matplotlib==3.9.3
numpy==2.2.0
pandas==2.2.3

Ainsi, une personne qui clone le projet peut recréer son propre environnement virtuel, puis réinstaller les mêmes bibliothèques localement.

Dans ce cours, vous n’aurez pas à gérer ce fichier. L’important pour l’instant est surtout de comprendre ceci :

  • le dossier .venv reste sur votre ordinateur;
  • GitHub conserve le code du projet;
  • si nécessaire, un fichier comme requirements.txt peut indiquer quelles bibliothèques doivent être réinstallées.
