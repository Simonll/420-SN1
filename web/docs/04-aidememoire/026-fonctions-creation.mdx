# Création de fonctions

Une fonction regroupe un bloc de code réutilisable sous un nom. \
Elle reçoit des données en entrée via ses **paramètres**, effectue un traitement, et peut renvoyer un résultat avec `return`.

---

## 🔹 Anatomie d'une fonction

```python
def double(x):
    return 2 * x
```

| Élément | Rôle |
|---|---|
| <C><K>def</K></C> | Mot-clé qui indique la définition d'une fonction |
| <C>double</C> | Nom de la fonction |
| <C>(x)</C> | Paramètre(s) entre parenthèses |
| <C>:</C> | Indique le début du corps de la fonction |
| Indentation | Délimite le corps de la fonction (obligatoire) |
| <C><K>return</K></C> | Valeur renvoyée à l'appelant |

---

## Les paramètres

Le paramètre est la variable déclarée dans la définition même de la fonction. C'est l'espace réservé (la « boîte vide ») qui attend de recevoir une donnée. Une fonction peut avoir 0, 1 ou plusieurs paramètres. 

```python
def nombre_pi():
    return 3.14159

def carre(x):
    return x * x

def puissance(base, exposant):
    return base ** exposant
```

- Les paramètres multiples sont séparés par des virgules.
- L'ordre des valeurs lors de l'appel doit correspondre à l'ordre des paramètres.

```python
puissance(2, 3)   # base=2, exposant=3 → retourne 8
puissance(3, 2)   # base=3, exposant=2 → retourne 9
```

---
## L'arguement

L'argument est la valeur fournie à un paramètre lors de l'appel de la fonction. C'est la donnée réelle qui remplit la « boîte vide » du paramètre.

```python
# 'masse' et 'volume' sont les PARAMÈTRES (les boîtes vides)
def calculer_concentration(masse: float, volume: float) -> float:
    return masse / volume

# 10.5 et 2.0 sont les ARGUMENTS (les valeurs concrètes)
resultat = calculer_concentration(masse=10.5, volume=2.0)

# Ici, le contenu de la variable 'poids_echantillon' devient l'ARGUMENT
poids_echantillon = 50.0
calculer_concentration(masse=poids_echantillon, volume=5.0)
```

---

## Valeur par défaut

Un paramètre peut avoir une valeur par défaut, utilisée si aucune valeur n'est fournie lors de l'appel.

```python
def puissance(base, exposant=2):
    return base ** exposant

puissance(5)     # exposant prend la valeur par défaut → 25
puissance(5, 3)  # exposant prend la valeur fournie → 125
```

Les paramètres **sans** valeur par défaut doivent toujours être placés **avant** ceux qui en ont une.

## Valeur de retour

| Situation | Comportement |
|---|---|
| <C><K>return</K> valeur</C> | Renvoie la valeur et arrête la fonction |
| Plusieurs <C><K>return</K></C> | Seul le premier atteint est exécuté |
| Retour multiple | <C><K>return</K> a, b</C> → décomposable en <C>x, y = f()</C> |
| Aucun <C><K>return</K></C> | La fonction retourne automatiquement <C><K>None</K></C> |

```python
def diviser(a, b):
    quotient = a // b
    reste = a % b
    return quotient, reste

q, r = diviser(10, 3)   # q = 3, r = 1
```

### Fonction sans `return`

Une fonction sans `return` retourne automatiquement `None`.

```python
def saluer(nom):
    print(f"Bonjour, {nom}!")

saluer("Mario")           # Affiche : Bonjour, Mario!
resultat = saluer("Link") # Affiche : Bonjour, Link!
print(resultat)           # Affiche : None
```

⚠️ N'affichez jamais le résultat d'une fonction qui ne retourne rien — cela affichera toujours `None`.

```python
# ✅ Bonne utilisation
saluer("Kirby")

# ❌ Mauvaise utilisation
print(saluer("Kirby"))   # Affiche la salutation, puis None
```

### Une fonction peut retourner une autre fonction

```python
def creer_courbe_calibration(pente, ordonnee):
    """
    Cette fonction principale est une usine. 
    Elle fabrique et retourne une nouvelle fonction sur mesure.
    """
    
# 1. On définit la sous-fonction à l'intérieur
def appliquer_calibration(valeur_brute: float) -> float:
    return (pente * valeur_brute) + ordonnee

# 2. On retourne la fonction ELLE-MÊME (attention : pas de parenthèses !)
return appliquer_calibration
```

## Portée des variables

| Portée | Définition | Accessible |
|---|---|---|
| **Globale** | En dehors de toute fonction | Partout dans le programme |
| **Locale** | À l'intérieur d'une fonction | Uniquement dans cette fonction |

```python
x = 10             # variable globale

def ma_fonction():
    x = 5          # variable locale — différente de la globale
    print(x)       # affiche 5

ma_fonction()
print(x)           # affiche 10
```

Les paramètres d'une fonction ont aussi une portée locale.

## Commentaires et docstring

```python
def energie_cinetique(masse, vitesse):
    """
    Calcule l'énergie cinétique d'un objet.

    Paramètres :
    masse (float)   : masse en kg
    vitesse (float) : vitesse en m/s

    Retourne :
    float : énergie cinétique en Joules
    """
    return 0.5 * masse * vitesse ** 2
```

| Syntaxe | Utilisation |
|---|---|
| <C><S># commentaire</S></C> | Commentaire sur une ligne ou en fin de ligne |
| <C><S>"""..."""</S></C> | Docstring : documenter une fonction (obligatoire bonne pratique) |

## Typage des fonctions (Annotations de type)

Le typage des fonctions (ou *type hinting*) permet de spécifier le type de données attendu pour les paramètres et la valeur de retour. C'est une pratique moderne qui rend le code plus lisible, plus robuste et plus facile à déboguer.

### 1. Clarifier le retour d'une fonction

Le typage permet de répondre de façon visuelle et explicite à la question de la différence entre `return` et `print`. Si une fonction ne fait qu'afficher un résultat sans rien calculer, on peut le déclarer officiellement avec `-> None`.

L'étudiant voit immédiatement que cette fonction ne lui redonnera aucune donnée utilisable pour la suite de son script :

```python
def afficher_vitesse(vitesse: float) -> None:
    print(f"La vitesse mesurée est de {vitesse} m/s.")
```

### 2. Améliorer l'autocomplétion dans VS Code

C'est ici que l'outil devient le meilleur ami de l'étudiant. En ajoutant des types, VS Code devient soudainement beaucoup plus intelligent.

Lorsqu'un étudiant appellera sa fonction plus tard dans son code, l'IntelliSense (la petite boîte d'aide de VS Code) lui rappellera exactement ce qu'il doit fournir. S'il a tapé `def calculer_masse(volume: float, densite: float) -> float:`, VS Code va le prévenir (avec un soulignement subtil) s'il essaie d'y insérer du texte par erreur. C'est un filet de sécurité énorme.

### 3. Renforcer la rigueur scientifique

En sciences, la nature d'une donnée est tout aussi importante que sa valeur. Savoir si on manipule un nombre entier (un nombre de cellules, une quantité de patients) ou un nombre à virgule flottante (une concentration, une distance) est fondamental. Le typage force l'étudiant à réfléchir à la nature de sa variable avant même d'écrire son équation.

### 4. Un indice, pas une contrainte stricte

Il y a cependant un "piège" conceptuel important à clarifier : Python reste un langage à **typage dynamique**.

Il faut bien expliquer aux étudiants que ces annotations sont des **indices** (*hints*) pour eux-mêmes et pour VS Code, mais que Python n'arrêtera pas l'exécution de lui-même si on "triche".

```python
# L'équation de l'énergie cinétique
def energie_cinetique(masse: float, vitesse: float) -> float:
    """
    Calcule l'énergie cinétique d'un objet.
    équation : E = 1/2 * m * v^2
    argument masse : masse en kg
    argument vitesse : vitesse en m/s
    retourne : énergie cinétique en Joules
    """
    return 0.5 * masse * (vitesse ** 2)

# Python autorisera ceci sans erreur fatale (bien que VS Code puisse souligner l'anomalie)
energie_cinetique(10, True)
```

C'est pourquoi on les appelle des **annotations** et non des contraintes strictes comme en C++ ou en Java.
