🕵️‍♂️ Trace d’exécution

Trace

Lorsqu'on a un morceau de code, on peut souhaiter savoir dans quel ordre les instructions sont exécutées.
On veut spécifier précisément :

  • Quelles lignes de code s'exécutent dans quel ordre.
  • Les effets de chaque ligne de code :
    • quelles variables sont créées/modifiées,
    • quelles valeurs elles contiennent,
    • ce qui est affiché (si on a des print).
  • La portée des variables.
  • Si on a des fonctions :
    • la pile d'appels (quelles fonctions sont en cours d'exécution),
    • quelle fonction est appelée,
    • quelle valeur elle retourne (si elle en retourne une).

👉 Vous pouvez imprimer ce tableau de trace d'exécution pour pratiquer vos traces à la main.

Dans le cas d'une séquence d'instructions, on peut voir que les instructions sont exécutées dans l'ordre de lecture du code. Simple!

Explications​

Le lien avec le débogage pas à pas

La colonne #ligne correspond exactement aux numéros de lignes que vous voyez défiler dans votre éditeur lorsque vous exécutez votre programme en mode débogage (pas à pas). Chaque ligne de la trace représente un moment précis de l'exécution, tout comme chaque fois que vous appuyez sur Pas suivant (Step Over / Step Into) dans le débogueur.

Produire une trace à la main, c'est donc faire le travail du débogueur dans votre tête.

Portée des variables

On indique la portée des variables en les regroupant par colonne (première ligne du tableau).
Ici, on a la portée globale (variables définies en dehors de toute fonction), la portée de affiche_resultat() et la portée de carre().

Remarques importantes :

  • La variable n n'existe que dans la portée de carre()
  • Les variables a, b et total n'existent que dans la portée de affiche_resultat()
  • La variable z est dans la portée globale, visible partout dans la trace
Fonction appelée et valeur retournée

On indique dans les dernières colonnes :

  • fonction appelée : la fonction exécutée
  • valeur retournée : la valeur que la fonction produit
Pile d'appels

On indique aussi la pile d'appels, c'est-à-dire les fonctions en cours d'exécution (3e colonne à partir de la droite).

Lorsqu'une fonction en appelle une autre (appels imbriqués), on peut visualiser la pile d'appels comme un empilement temporaire où :

  • Chaque appel s'ajoute au sommet de la pile
  • Chaque retour de fonction retire l'appel du sommet

Par exemple, dans ce code, affiche_resultat() appelle carre(), ce qui crée une pile imbriquée.

Voici maintenant un petit exemple qui démontre l'importance de spécifier la portée des variables, où on a une variable x dans la portée globale et une autre variable nommée x dans la portée de la fonction ma_fonction().

Code​

def ma_fonction(y):
    x = 3 + y
    print(f'dans ma_fonction, x vaut {x}')

x = 5
print(f'dans main, x vaut {x}')
ma_fonction(100)
print(f'dans main, x vaut toujours {x}')

Portée des variables : masquage (shadowing)

Cet exemple démontre l'importance de bien distinguer les portées. On a une variable x dans la portée globale et une variable x dans la portée de ma_fonction().

Observations clés :

  1. La variable x locale ne modifie pas la variable x globale
  2. L'instruction x = 3 + y crée une nouvelle variable locale x dans ma_fonction()
  3. Cette variable locale masque (shadows) la variable globale x
  4. Après le retour de ma_fonction(), la variable globale x garde sa valeur initiale

Conseil : Si tu voulais modifier la variable globale x dans ma_fonction(), il faudrait utiliser le mot-clé global (ce qui est généralement déconseillé en programmation).

  • Certaines lignes ne s'exécutent pas, c'est le principe de la condition!
  • On indique les lignes qui testent une condition : if, elif, match, case (mais pas else ni case _).

Afin de valider une trace :

  1. Placer un point d'arrêt sur la première ligne qui s'exécute.
  2. Lancer l'exécution en mode débogage.
  3. Sauter de ligne en ligne pour voir si la trace est correcte.

Si on se rend à la fin de l'exécution et que toutes tes valeurs étaient bonnes, on a bien compris ce que fait le code.

Pour plus de détails sur le placement de points d'arrêt et l'utilisation du débogueur, voir la recette Déboguer et points d'arrêt.
